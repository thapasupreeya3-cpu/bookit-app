# The Care Web — v88.2.3 changelog

11 September 2026 · Worker document display fix · Updates v88.2.2.

## What was wrong

The verification workspace displayed every worker document-table record in a single list. That table also holds certificates generated by the site's training modules, even though those records have no uploaded files. Missing document types were omitted entirely, and records containing only entered details could be labelled “Ready for review.” This made a training-only or incomplete file confusing.

The existing upload API does store worker copies in that same table. Testing did not find a filter that dropped genuine uploaded files from the prior API. This release corrects their presentation and makes absent copies explicit; it does not claim to recover documents from a live database that was not available here.

## Changes

- **Worker documents** now groups Identity, Right to work, Checks and clearances, Uploaded training certificates, Qualifications and resume, and Other worker documents.
- **Training** contains the site's module completions and their platform-issued certificate records. The document count excludes those generated records. Classification uses the worker's own completion link, not words in a filename or title.
- Uploaded First Aid, CPR, NDIS orientation and external course certificates remain in Worker documents. Legacy/custom document types and attached files remain visible, including an uploaded file referenced by an older module record.
- A record without an attached copy says **Details only · file not uploaded**. It is not shown as ready to verify. Existing agreement acceptance records for participants retain their treatment.
- Missing evidence options appear under their category. Identity alternatives and optional documents are not all treated as mandatory. **Request copy** selects the correct document type; the office still reviews and confirms the message. Existing requests are identified.
- Accounts with no uploads explicitly show **No worker files have been uploaded to this account**, even if training is complete.
- Queue counts refresh immediately after the update. Versioned workspace asset URLs refresh cached JavaScript and CSS.
- The sample preview now includes distinct illustrative passport, screening, resume and CPR attachments. The previous preview incorrectly reused its CPR illustration for the passport. All samples remain labelled and contain no real worker data.

## Use the update

Extract the small update ZIP, merge its contents into the existing repository root, and replace matching files while keeping unchanged files. Restart/redeploy using your usual process, then refresh Admin → Verification. Read UPDATE-INSTRUCTIONS.txt in the archive.

**Preserve the deployed database, uploaded documents, photos and configuration.** This source ZIP intentionally excludes runtime data. No new database migration is needed from v88.2.2; the schema remains 88202. Earlier verification automations and final reviewer decisions are retained.

If a worker still shows zero uploads, check that you opened the correct worker account and that its files have actually been uploaded to the deployed site's worker document store. Documents held only in an external folder or a company-level forms register are not individual uploaded copies. The app cannot display those files until they are filed against the worker.

## Validation and limits

All **36 verification scenarios** and the full `npm run check` release gate passed. Upgrade checks preserved records and uploaded bytes on two consecutive boots. See TEST-RESULTS.md for the completed release checks. Regression coverage includes worker uploads across 12 document types, actual module completion, protected original-file access, mixed legacy records, missing-file labels, request selection, training-only accounts and refreshed counts.

No live worker database was supplied or changed. Browser rendering and PDF interaction require staging verification; local browser access was blocked in the previous verification run. The available test runtime is Node 24.19.0; repeat the release check on the declared Node 22 host.
